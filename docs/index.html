Computation, Not Memory: Chain-of-Thought and State Tracking in LLM Agents

Pedram Mouseli    Massieh Moayedi

University of Toronto

Paper Code BibTeX
Language-model agents often reason before they act, and proposals to monitor such agents depend on how their actions relate to that reasoning. Reasoning could help an agent in two ways: as computation when it decides what to do, or as memory that it keeps for later turns. We separate these roles in a small file-system task where the correct action depends on a changing lock state, using Qwen3-8B and Qwen3.5-9B. Reasoning written at the moment of action prevents most rule violations, while retaining earlier reasoning in the prompt adds little. The agent acts on the reasoning in its context, and the state that can be decoded from its activations without reasoning does not tell which interventions change its actions.

The task

Moving files while locks change in the background

The agent works in a small file system with three log files and report.txt. It must archive every unlocked log file, never touch a locked file, and leave report.txt locked. After the agent's second, fourth and sixth commands, a background job toggles the lock of one file. The announcement names the file but not its new value, so the agent has to work out the current locks from its history.

Question 1

Generating reasoning matters more than retaining it

Reasoning can help in two ways. Generating it before an action gives the model extra computation at the moment of decision. Retaining it in later prompts gives the model notes that it could consult instead of working out the state again. We vary the two separately. The observations and executed commands always stay in the prompt.

Question 2

The content of the reasoning matters

Agents that reason also end up in different states from agents that do not. To compare like with like, we take 400 saved prompts and complete each one with a different thought block. Only the thought block changes.

Question 3

A state that can be decoded is not necessarily the one that is used

Without reasoning, can we read the state from the model instead? Linear probes recover the lock state from the activations about as well as a text classifier recovers it from the transcript (balanced accuracy 0.79 and 0.77). To test which directions affect the model's answer, we ask "Is the file locked?" on both versions of a counterfactual pair. We then copy the locked version's activation at the final token into the unlocked version, along one direction only. The recovered fraction R says how far this moves the answer: 0 means no change, and 1 means the answer of the locked version.

The logistic probe decodes the state almost perfectly from layer 22 on, but never recovers more than 0.02. R can slightly exceed 1 when a patch moves the answer a little past the locked version's answer, as the counterfactual direction does in the last two layers. On the same prefixes, the state question and the direct action also depend on different parts of the context (Section 7 of the paper).

Takeaways

  • In this task, the benefit of reasoning for rule-following comes mainly from generating it at each step, not from retaining it as memory.
  • The benefit depends on what the reasoning says, and the agent's next action follows the reasoning in its context.
  • An accurate readout of the state, from probes or from the model's answers, does not show how the state reaches the action. Readouts should be tested against the behavior they are meant to explain.
